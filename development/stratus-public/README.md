# Stratus public showcase

Public, read-only shader showcase with a private feedback submission form. Visitors cannot edit specifications, queue shader work or access developer APIs. The separate Studio remains owner-private.

## Automatic release images

`work/stratus-studio/public_sync.py sync` runs every minute in the existing Mac bridge. It selects the numerically latest release whose full version ends in `0` (for example 1.6.0, 1.6.10 or 1.9.100), with a matching package SHA, loaded-release install receipt and at least two actual release captures. Both legacy and current install-receipt formats are recognised. Final-pack images in the visual report must be reviewed and match their capture hashes; menus and QA variants are excluded. Versions ending in other digits, such as 1.6.11, never refresh the showcase. Existing published images stay visible until a newer eligible release has verified captures. It uploads up to ten versioned PNGs and atomically replaces the public release feed only after at least two valid images exist. An unchanged local fingerprint is checked against the live feed, so a missing or reverted gallery can be republished. Release changes need no website redeployment or developer-home configuration. New browser sessions fetch the feed; open pages refresh every minute. The Mac must be awake for uploads; published content remains hosted while it is offline.

Release convention: `outputs/Stratus-VERSION-install.json` records `version`, `sha256`, `release_loaded: true`, `runtime_pack: Stratus-VERSION.zip`, `verification_date` and `runtime_evidence`. Put selected real captures from that loaded pack in `outputs/Stratus-VERSION-showcase/*.png`. Legacy captures named `sVERSIONDIGITS-release-*.png` beside the receipt's runtime evidence under screenshots/ are also discovered, excluding menu/restored-state frames. No synthetic images or unrelated older captures. If new verified images are absent the previous labelled release stays visible. Packaging alone never relabels an image.

The live release card and main gallery use `/api/release` and versioned `/api/images/` objects. The longer curated specification/release history and explicitly dated historical illustrations remain reference content; the live feed does not turn historical verification into current evidence.

## Feedback

Anonymous same-origin POST `/api/feedback` validates topic, message, optional reply email, honeypot, length, elapsed time and submission UUID. A hashed hourly source limit and daily global limit constrain submissions. Feedback is stored in D1 and never exposed through public reads. A server secret protects `/api/manage/feedback` and all release writes. The secret and owner email are never in browser code.

Server delivery is implemented in `lib/feedback-mail.ts`. Runtime secrets `RESEND_API_KEY`, `FEEDBACK_TO` and optionally `FEEDBACK_FROM` configure Resend; `FEEDBACK_DELIVERY=server` enables it after configuration. The destination is fixed by the server. New submissions are committed to D1 before a Worker background task sends plain text through the HTTPS API. The browser receives no email credential or owner address. Provider acceptance is saved as a `resend:` receipt; this does not certify Inbox placement. There is no model, ChatGPT automation, Gmail connector or Mac dependency for submission delivery.

Durable per-message leases prevent concurrent senders. A frozen payload and stable idempotency key allow retrying an uncertain API response within 23 hours (the provider retains keys for 24 hours); older uncertain work is held as `unknown` for provider-receipt review. Retry delays back off, respecting numeric Retry-After responses. New submissions and the existing public release/update feed refreshes drain up to three eligible records per request. Retries therefore resume on subsequent website traffic; this host has no configured independent timer. Feedback remains stored when nobody visits. A configured verified sender domain is recommended for production; the provider's default `onboarding@resend.dev` sender is restricted to its account owner's inbox.

The standalone `work/stratus-studio/feedback_mail.py` refreshes the private local cache, including hosted receipts, whenever this Mac is online. With hosted delivery enabled it does not authenticate to SMTP or send. Cloud claim checks also reject the legacy sender, preventing duplicates during handover. Without hosted configuration, the existing Gmail SMTP setup remains available: `feedback-mail-setup.command` saves a Google app password in Keychain and installs a minute-based LaunchAgent. Its uncertain deliveries are never silently replayed by the cloud sender. The previous ChatGPT automation is paused.

## Hosting

Vinext Worker with D1 `DB` and R2 `BUCKET`. Runtime secrets: `UPDATE_KEY` and the feedback configuration above. Authored browser files live under `public/`; `dist/` is generated. The Sites helper builds and publishes. Schema migrations are generated by `npm run db:generate` and applied at deployment. Hosted email credentials are stored through Sites runtime secrets; local Gmail credentials stay in macOS Keychain. Neither is committed.

## Every release: automatic public notes

The Mac background uploader also publishes `/api/updates` every minute, independently of showcase image updates. It reads completed version headings and the `At a glance` bullets from CHANGE-LOG.md, requires a matching packaged ZIP and install-receipt SHA, strips local links/paths and emits plain-text release notes. Candidate/test headings are excluded. All patch releases are included; gallery refreshes remain limited to versions whose last digit is 0. No model, ChatGPT automation, chat handoff or per-release website redeployment is involved. Changes to the documented summaries refresh the feed too. Public visitors have read-only access; writes require the existing update service credential.

The release process must record final releases in the change log using `## DATE — Stratus VERSION` and `### At a glance`, as the existing releases do. This is release documentation, not website configuration. Without a completed release record and matching package receipt, the updater keeps the existing notes. The Mac must be awake and online for uploads; published notes remain online while it is offline.

## Atmospheric redesign

Original Stratus layout inspired by the cinematic composition of igloo.inc: full-viewport real game photography, corner annotations, oversized typography, drifting fog, glass/backdrop blur, pointer depth and native-scroll focus changes. No Igloo source, models, textures or audio are copied. Effects are standalone CSS/JavaScript; the operating system reduced-motion preference is respected and Motion can also be disabled. Mobile effects use smaller movement and blur budgets. Release data, protected feedback and the read-only public boundary are preserved.

Pre-redesign backup: `backups/stratus-public-before-igloo-20261022-214335/` in the project root contains source, source history, deployment build, public R2 feed snapshots/images, checksums and restoration instructions.

Curated `outputs/Stratus-VERSION-showcase/showcase.json` entries supply public scene titles and settings descriptions and must match each PNG hash. A QA-named pack may be used for curated captures only after its shader runtime assets are verified byte-identical to the final release; describe the preset difference explicitly. Original source captures are preserved.

## Public privacy boundary

Only curated shader copy, public release notes and approved game captures are served. The unused developer seed snapshot has been removed from this source. Owner addresses, identity and the Studio destination are runtime secrets, not public assets. The small Studio link uses `/api/studio`: ChatGPT sign-in is required, and only the configured owner is redirected to the private Studio. Public feedback and management reads remain protected by the service secret. Feedback is never included in release feeds. Outgoing links use a no-referrer policy.

Public release writes and reads reject owner identifiers, email addresses, local filesystem paths and recognisable credential strings. These checks are a guard against accidental disclosure; approved image content and prose still require review. The hosting account name remains part of the platform's public hostname. A custom domain is needed to hide that hostname from visitors. Removing a file from current source does not erase any prior public Git history or backups.
