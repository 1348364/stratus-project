# Stratus project instructions

For shader work in this project, follow `work/Custom instructions/AGENTS.md` the standing priorities in `work/Custom instructions/GOALS.md`, and the efficient execution rules in `work/Custom instructions/WORKFLOW.md`.

`work/Custom instructions/TASK.md` is the complete long-term shader target and clean-rebuild specification, not the next coding pass. `work/Custom instructions/CHANGES.md` contains the pending incremental work. When the user says “Apply the pending changes” or otherwise asks to implement the current change brief, read both files and implement only pending requests in `CHANGES.md` while preserving the rest of `TASK.md`. If no pending request is filled in, report that there is no new work. `CHANGE-LOG.md` records finished implementation. `SPEC-BASELINE.md` is a legacy comparison snapshot, not a task trigger. In-game setting defaults and choice lists live in shader source. Saving a file alone does not trigger work.

After every completed shader change, reconcile `TASK.md` against actual source, options, presets, packaged release and verification evidence. Incorporate approved completed design changes and refine stale wording without changing the user's intended target or overwriting newer edits. Keep unfinished or unverified items pending in `CHANGES.md`; move completed, verified items out of Pending changes into `COMPLETED-CHANGES.md` and record evidence in `CHANGE-LOG.md`. If the queue is empty, leave “No pending changes.” A Studio run explicitly moves the submitted Pending changes into a separate durable `IN-PROGRESS/<request-id>/CHANGES.md` batch and clears only the submitted version of the shared queue for new requests. This move is not completion. During a batch run, stage and reconcile only its active brief, leave unfinished or unverified work in that batch, and preserve the shared CHANGES.md for later unsent requests. Outside this authorised batch move, never clear pending work just because it was sent or a turn ended. Never rewrite the target just to match incomplete code. Follow the detailed reconciliation procedure in `work/Custom instructions/AGENTS.md`.

When the user asks for a prompt, draft or refine the instructions without implementing shader code unless they also ask for implementation.

In the prompt-generator chat, review `CHANGES.md` and the relevant parts of `TASK.md` when the user asks for feedback or handoff. Make small clarifying edits that preserve intent, then send the coding chat a concise summary of pending items only if the user has authorised the handoff. Report what was changed and sent. Do not treat a file save alone as the trigger.
